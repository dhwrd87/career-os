# Learning Path Intelligence V1 — final subsystem reconciliation

The original V1 engine, twelve model contracts, methodology and historical decisions were recovered from the existing productization tree and read-only reference integration standard, evidence capture routine, learning report and conversion-intelligence implementation. The core first landed in 0.3.20; it was already present in the recovered 0.3.22 tree. Specifications were reconciled against executable behavior rather than counted as delivered features. No parallel recommendation framework or private career dataset was introduced.

| Acceptance area | Recovered V1 foundation | 0.4.1 working connection and evidence |
|---|---|---|
| Knowledge, skill, credential, experience and evidence gaps | CareerGapPriorityV1; live qualification gaps and evidence weakness | `learning gaps` retains requirement subtype, approved career gaps and unsupported canonical claims; e2e asserts typed categories |
| Market-driven requirements | Observed job frequency, required/preferred importance, hard-gap recurrence | Current selected family and saved qualifications source each gap; individual sample boundary displayed |
| Severity and priority | Existing bounded priority dimensions/classes | Unchanged V1 scoring; source details/qualification IDs retained |
| Live resource discovery | Optional provider-neutral adapters, historically caller-supplied catalogs | Public HTTPS sitemap/course page reader; actual OCW retrieval observed, synthetic reader/privacy/error tests; unsupported authenticated APIs remain explicit |
| Provider-neutral evaluation | Seventeen dimensions and four-value model | Same engine for all providers; comparison/exclusion report; commercial adjustment always zero |
| Personalized roadmap | Minimal course reuse, typed steps and evidence plan contracts | Saved preferences and profile knowledge feed engine; sequenced original projects, gaps without eligible options disclosed |
| Budget, time, subscriptions | Preference inputs in V1 | Individual and aggregate constraints enforced; current verified price/currency and explicit plan coverage; unknown facts block strict constraints |
| Freshness and redundancy | CourseFreshnessV1 and LearningRedundancyV1 | Unknown/future/stale/removed records excluded; prior verified learning and current knowledge included |
| ROI and career impact | LearningROIV1; LearningPathImpactV1 | Selected-path descriptive ROI, qualification impacts and explicit unsatisfied experience actions; no salary or hiring prediction |
| Practical evidence | EvidenceCreationPlanV1; completion proposal | Inspectable originals, test/review notes and human verification; hashes rechecked before promotion |
| Training completion | Personal integration lifecycle | NOT_STARTED → IN_PROGRESS → COMPLETED → VERIFIED; append-only events with source/date/prior/current/class/hash and separate projections |
| Profile/credentials | Existing canonical changeset governance | Verified artifacts plus explicit bounded claims create proposals; actual awards distinguished from preparation/completion certificates; approval/transaction commit reused |
| Eligibility reassessment | Rebuild profile/family/qualification after approved evidence | Executable reassessment retains selected family and reports before/after/remaining gaps; completion alone changes no eligibility |
| Skill and navigation | Historical learning intent vocabulary | All intents map to executable commands; focused supporting skill reference; always-visible workspace module, README/features/examples |
| Actual presentation | Reference Markdown integration and evidence routine | Generated HTML/Markdown/PDF with consistent report hierarchy; rendered desktop/mobile/PDF gallery; no private UI copied |

The workflow acceptance suite completes the actual project → verified artifact → proposed changeset → human approval → canonical commit → profile rebuild → eligibility reassessment path. It checks that Python evidence improves the skill gap while the professional-experience requirement remains unsatisfied. Separate tests cover actual awarded credential proposals, strict constraints, stale artifact rejection, repeatability, privacy and offline failure recovery. The original nineteen V1 tests remain in place, including affiliate invariance and hard prerequisite boundaries.

Historical decisions preserved: provider-neutral ranking; four distinct values; generic local discovery queries; factual freshness; no static course canon; no automatic canonical promotion; no course-hoarding objective; and no experience equivalence without an employer's actual policy. Optional affiliate metadata stays separate from the ranking function. Owner review remains necessary for public release.
