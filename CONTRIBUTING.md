# Contributing

Use Python 3.11 or 3.12, install `.[resume,docx,dev,test]`, and put Poppler on PATH. Keep runtime workspaces and caches outside the source checkout. Run `python -m unittest discover -s tests -v` and the relevant installed-wheel persona flow before proposing a change.

Use only fictional identities, reserved example domains and synthetic work samples in issues, tests and pull requests. Do not upload resumes, private job-search records, credentials, employer-confidential evidence or real contact data. Public bug reports should describe the failure and include a minimal synthetic reproduction.

Maintain package/data/state/output separation, evidence provenance, canonical approval boundaries and immutable submitted artifact hashes. Tests must demonstrate behavior or protect a meaningful invariant. Do not weaken a quality gate or refresh a visual golden merely to get a passing build. Explain any intentional geometry change with generated before/after artifacts; golden approval is a separate reviewed change.

Keep the skill focused on orchestration. New user-facing capabilities need executable package commands, a documented skill route and a realistic fixture. A successful fixture is not evidence of support for an untested AI host, ATS vendor or operating system.
